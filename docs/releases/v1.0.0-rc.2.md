# SecureFlow v1.0.0-rc.2

<!-- secureflow-release-state: final -->

This release candidate packages the SecureFlow Security Case boundary for install-once use across agent tasks. It is a prerelease for interoperability and local workflow evaluation, not a stable or production-readiness claim. The immutable `v1.0.0-rc.1` tag remains unchanged.

## Highlights

- `secureflow mcp` exposes one provider-neutral stdio server that accepts a bounded local Security Case path per call, allowing one installation to work with different authorized cases without restarting configuration.
- Four narrow tools validate a case, list candidates, investigate evidence, or stage a recommendation in a distinct new derived file without replacement. Tool annotations distinguish read-only operations from staging, and no MCP dispatch route can record a final human decision.
- A Codex plugin packages the MCP configuration and a thin `secureflow-security-case` skill that preserves authorization, treats artifact content as untrusted data, prefers abstention when evidence is insufficient, and keeps `case-decide` outside agent authority.
- The project marketplace and installer provide a reproducible local Codex setup. A separate launcher starts the existing Review Room on loopback only and retains its WebMCP read/draft boundary.

## Verification and artifacts

The candidate requires pinned Rust 1.92.0 formatting, Clippy with warnings denied, workspace tests, plugin and skill validation, Review Room tests/lint/build/audit, a real stdio handshake, a localhost launcher smoke test, dependency audit, and the existing local release controls. Hosted tag publication must bind the exact tag, build run, retained artifact digest, archive checksums, attestations, and staged release uploads before publishing.

## Limits and authority

MCP and WebMCP are access surfaces, not vulnerability authorities. Case paths are selected by the calling local host and remain subject to operating-system permissions and host consent. SecureFlow does not add target crawling, active scanning, exploitation, autonomous patching, provider transport, a complete-security guarantee, or demonstrated superiority over human researchers. Only a named person using `secureflow case-decide` with retained rationale may add a final `validated`, `rejected`, or `abstained` decision to a derived case.
