# SecureFlow v1.1.0-rc.4

<!-- secureflow-release-state: draft -->

This local release candidate makes large Security Case reviews more efficient without weakening SecureFlow's evidence or human-authority boundaries. It is an evaluation candidate, not a stable or production-readiness claim.

## Highlights

- Universal MCP and Review Room WebMCP expose aggregate candidate summaries and bounded, filterable pages before full evidence inspection.
- WebMCP candidate-key schemas remain constant-size instead of embedding every loaded candidate ID.
- Review Room filters by review state and severity, groups repeated exact signals, and keeps the queue paginated. Grouping never transfers a verdict.
- The bundled skill instructs agents to use summary → filtered page → selected investigation and to avoid repeating the full candidate set.
- Hosted CI now verifies Review Room tests, lint, build, and production dependency audit alongside the Rust gates.

## Retained evidence

The authorized nine-case Mitiquete set contains 53 candidates. On its largest 38-candidate component, the new summary plus first 20-item page serializes to 6,411 UTF-8 bytes versus 15,585 bytes for the former full response. The candidate-key schema measures 32 bytes versus 2,571 bytes for the former 53-entry dynamic enum. See `docs/evidence/mitiquete-review-efficiency-2026-09-20.md` for scope and limits.

These byte measurements are not token, billing, latency, or model-quality claims. SecureFlow still makes no automatic vulnerability decision, does not transfer decisions across grouped candidates, and adds no crawling, exploitation, provider transport, autonomous patching, merge, or deployment.
