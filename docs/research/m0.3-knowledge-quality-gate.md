# M0.3 knowledge-base quality and scale gate

Status: **50k/100k synthetic gate passed; real-source efficacy is not measured**.

## Decision

SecureFlow may use a 50,000-record optional catalog for an MVP and may test a 100,000-record catalog on the measured workstation. It must not call either count “validated vulnerabilities.” Source records, canonical exact-alias components, malicious-package reports, advisory records, and human-validated SecureFlow findings remain distinct quantities.

The M0.3 gate uses deterministic OSV-shaped synthetic records in `crates.io`, npm, and GitHub Actions. Every tenth source record carries an exact alias to the preceding synthetic CVE, so 50,000 and 100,000 inputs must produce exactly 45,000 and 90,000 canonical components. Text or AI similarity is never used for this merge.

## Pass criteria

- Both 50,000 and 100,000 source-record rows complete from fresh databases without retaining the generated corpus.
- Canonical counts exactly match the generator’s declared alias model.
- SQLite `quick_check` returns `ok`, foreign-key violations equal zero, and FTS status is `ready`.
- At 100,000 records, the database stays below 256 MiB, total ingestion stays below 30 seconds, and throughput stays above 3,000 records per second on the documented host.
- At 100,000 records, median exact identifier and package lookups stay below five milliseconds and the declared broad, low-selectivity FTS scenario stays below one second.
- SecureFlow performs no network request and no model call during generation, ingestion, deduplication, integrity checks, or queries.

The retained direct run passed each gate: 100,000 synthetic source rows produced 90,000 exact-alias canonical rows, the database used 209,502,208 bytes, ingestion and indexing took 6.870 seconds, exact identifier lookup had a 68.7 microsecond median, exact package lookup had a 156.142 microsecond median, and the broad FTS query had a 78.585 millisecond median. “Canonical rows” describes structural upstream alias components; it does not mean human-validated vulnerabilities.

FTS is the measured query bottleneck. Across the retained Rust 1.92 runs, its broad-query median ranged from about 76.1 to 105.5 milliseconds while exact identifier and package lookups stayed below 0.3 milliseconds in the final direct run. A measured `cargo run --release` process tree peaked at 571,660 KiB, but that number includes compilation and linking; the already-built benchmark process covering both sizes peaked at 100,552 KiB. Neither value is a per-size runtime peak.

The benchmark now emits expected canonical counts, exact alias reduction, `quick_check`, foreign-key state, FTS readiness, and explicit dedup/integrity booleans. This prevents a fast but structurally invalid catalog from passing.

## Evidence lanes

The measured rows in [`catalog-quality-gate-2026-08-30.csv`](../evidence/catalog-quality-gate-2026-08-30.csv) are synthetic capacity evidence. The machine-readable interpretation and host limits are in [`catalog-quality-gate-2026-08-30.json`](../evidence/catalog-quality-gate-2026-08-30.json).

The retained real-source lane remains [`real-advisory-expansion-2026-08-25.json`](../evidence/real-advisory-expansion-2026-08-25.json): 263,522 source records produced 251,657 exact-alias canonical security records, with advisory and malicious-package classes reported separately. That real-source catalog was not rerun for M0.3, and its latency is not inherited from the synthetic rows.

## Limits before 300k or one million

The databases are fresh for ingestion, but the query samples are same-process, post-ingestion, warm or partially warm, and order-dependent; cold-start query latency is not measured. Five samples do not establish p95 or p99. The hardware result applies to the documented Ryzen 7 5700X, NVMe/Btrfs Fedora workstation and is not portable to low-power devices. Semantic-deduplication quality, crash recovery under load, concurrent writers, and five to twenty million relationships remain unmeasured. Those gates come before distributing a 300k–500k catalog or treating one-million-record synthetic capacity as a product requirement.
